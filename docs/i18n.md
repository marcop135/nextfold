# Add a language

The site ships in English at `/` and German at `/de`. Follow these steps to add another language, using Italian (`it`) as the example. Translation terms live in the [translation glossary](translation-glossary.md).

## How languages work

- **Routes.** Pages live under [`src/app/[locale]`](../src/app/[locale]), each language with its own root layout and `<html lang>`. [`proxy.ts`](../src/proxy.ts) rewrites unprefixed URLs to `/en` internally and redirects `/en/...` to the unprefixed URL.
- **Content.** One Sanity document per page and language, linked by slug. The `language` field is set by the template the editor picks and cannot change afterwards. A slug is unique within its language.
- **Seed copy.** Pages bundled with the code in [`src/content/seed`](../src/content/seed), one file per language. They render until Sanity has a published page with the same slug and language.
- **Fallback.** [`getPage`](../src/sanity/lib/fetch-page.ts) tries four sources in order: Sanity in the requested language, the seed copy in that language, Sanity in English, the English seed copy. When the content comes from English, the note above the footer tells the visitor that the page has no version in their language yet.
- **Interface strings.** [`messages.ts`](../src/lib/messages.ts) holds the words around the content. Every language is typed against `en`, so a missing key fails `npm run typecheck`.

## Steps

Steps 1 to 6 can run in any order; run 7 and 8 after them.

1. Add the code to `locales` and its names to `LOCALE_NAMES` in [`i18n.ts`](../src/lib/i18n.ts):

   ```ts
   export const locales = ["en", "de", "it"] as const;
   ```

2. Add an `it` object to [`messages.ts`](../src/lib/messages.ts), typed `Shape<UiMessages>` like `de`, and register it in `MESSAGES`.
3. Add `SITE_DESCRIPTIONS.it` in [`site.ts`](../src/lib/site.ts) and an `it` heading in `HEADINGS` in [`llms.txt/route.ts`](../src/app/llms.txt/route.ts).
4. Translate the fixed pages: in [`static-pages.ts`](../src/content/static-pages.ts), add `forAgentsIt` and `privacyIt`, then add them to the `forAgents` and `privacy` records at the end of the same file.
5. Create `src/content/seed/it.ts` with the same slugs as [`en.ts`](../src/content/seed/en.ts), each page with `language: "it"`, and add it to [`seed/index.ts`](../src/content/seed/index.ts) and to `languages` in [`content-check.mjs`](../scripts/content-check.mjs).
6. Add an Open Graph route at `src/app/og/it/[slug]/route.tsx`, a copy of [`og/de/[slug]/route.tsx`](../src/app/og/de/[slug]/route.tsx) with `"it"`.
7. Regenerate the Sanity types, because the `language` field's options changed:

   ```bash
   npm run typegen
   ```

8. Check the result:

   ```bash
   npm run typecheck
   npm run content:check
   npm run build
   ```

   `content:check` fails while an Italian seed page breaks a length limit or a slug is missing from one language.
9. Import the Italian seed pages into Sanity, or create them in the Studio from the **Page, Italiano** template. Both need a Sanity login with access to the project, set up in [Sanity setup](sanity-setup.md):

   ```bash
   npm run seed:import
   ```

The language switch, `hreflang` links, sitemap alternates, Markdown twins at `/it/<slug>.md`, Presentation routes, and the Studio desk lists all read `locales`, so they pick up the new language without further changes.
